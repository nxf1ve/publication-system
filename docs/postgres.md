# Локальный запуск с PostgreSQL

На этом компьютере используется установленный PostgreSQL 16, служба `postgresql-x64-16`, порт 5432. Создана база `publication_system`. Таблицы `users` и `publication` создаёт Hibernate при запуске сервера (`ddl-auto: update`). Docker не требуется.

Из корня проекта в PowerShell:

```powershell
# При первом запуске на другом компьютере с PostgreSQL:
powershell -ExecutionPolicy Bypass -File scripts/setup-db.ps1

# Терминал 1 — API, порт 8080
cd server
mvn.cmd spring-boot:run

# Терминал 2 — из корня проекта
npm.cmd run dev
```

Открыть http://localhost:5173, зарегистрировать аккаунт, затем перейти в «Каталог». Начальная база пустая. Добавление, редактирование и удаление выполняются через REST API; данные доступны после перезапуска сервера и браузера.

Нужны JDK 17+ и Maven. На этом компьютере `mvn.cmd` использует JDK 21; команда `java` из PATH указывает на старую Java 8, поэтому запускать сервер следует через Maven или явно указанный JDK.

По умолчанию локальное подключение: `jdbc:postgresql://localhost:5432/publication_system`, пользователь `postgres`, пароль `postgres`. Эти значения предназначены для локальной разработки. Переопределения задаются в терминале сервера перед запуском:

```powershell
$env:DB_URL = 'jdbc:postgresql://localhost:5432/publication_system'
$env:DB_USERNAME = 'postgres'
$env:DB_PASSWORD = '<ваш пароль>'
$env:JWT_SECRET = '<случайная строка минимум 32 байта>'
mvn.cmd spring-boot:run
```

При изменении адреса API задать `VITE_API_URL` в окружении клиента. Разрешённые адреса клиента: `localhost:5173` и `127.0.0.1:5173`.

Все вошедшие пользователи видят каталог. Изменять и удалять запись может создавший её аккаунт или ADMIN. Поле «Сотрудник» — отображаемое имя; проверка прав использует серверную связь с аккаунтом, которую нельзя подменить полями формы. Пароли и сущности пользователей в ответ каталога не попадают.

Данные старого прототипа остаются в ключе `publication-prototype-data` в localStorage браузера. Автоматический перенос не выполняется: у старых записей нет подтверждённого владельца в базе.

## Начальный администратор

Первый аккаунт ADMIN создаётся при запуске сервера с переменными окружения:

```powershell
$env:ADMIN_USERNAME = 'admin'
$env:ADMIN_PASSWORD = '<задайте пароль от 8 символов, максимум 72 байта UTF-8>'
cd server
mvn.cmd spring-boot:run
```

Без этих переменных автоматическое создание отключено. Пароль хешируется BCrypt и не записывается в репозиторий. Существующий ADMIN не изменяется при повторном запуске. Если логин занят сотрудником, запуск с такими настройками завершается ошибкой, а роль сотрудника остаётся прежней. После создания переменные можно убрать: аккаунт хранится в PostgreSQL.

## Проверки

```powershell
npm.cmd run build
npm.cmd test
npm.cmd --prefix client run test:e2e
cd server
mvn.cmd verify
```

Браузерные тесты используют изолированные ответы API. Для проверки настоящей базы при запущенном сервере из корня проекта:

```powershell
python scripts/check_postgres.py
```

Скрипт проверяет регистрацию, CRUD, серверную валидацию, аутентификацию, запрет изменения чужих записей и наличие/отсутствие данных прямыми SQL-запросами через `psql`. Созданные им аккаунты и публикации удаляются в конце. Используются локальная база `publication_system`, `DB_USERNAME`, `DB_PASSWORD`, `PGHOST`; URL API можно изменить через `TEST_API_URL`.

Для проекта остаются следующие задачи: поиск и пагинация, загрузка файла, полноценные профиль и админ-панель, аналитика. Для управляемых изменений схемы при дальнейшем развитии потребуется перейти с `ddl-auto: update` на версионированные миграции.
