## Проверка авторизации

1. Запустить PostgreSQL и создать БД `publication_system`. Настройки подключения: `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`.
2. В `server` выполнить `mvn spring-boot:run`. Для окружения вне локальной разработки задать `JWT_SECRET` (минимум 32 байта).
3. В корне выполнить `npm.cmd run dev`, открыть `/login`, зарегистрироваться и проверить выход и повторный вход.
4. После перезагрузки страницы сессия восстанавливается через `GET /api/auth/me`. Истёкший или недействительный JWT приводит к выходу при запросе к API.

API: `POST /api/auth/register`, `POST /api/auth/login` принимают `{username, password}` и возвращают `{accessToken, user: {id, username, role}}`. Логин: 3–50 латинских букв, цифр или `_.@+-` (можно использовать email); пароль: 8–72 символа и максимум 72 байта UTF-8 (ограничение BCrypt).

Самостоятельная регистрация всегда выдаёт USER. Для локальной проверки администратора роль существующего пользователя можно изменить в PostgreSQL: `UPDATE users SET role = 'ADMIN' WHERE username = 'admin';`. Роль берётся из БД при каждом запросе, а не из клиентских данных.

`/api/admin/**` требует ADMIN; остальное API, кроме регистрации и входа, требует JWT. Админ-панель пока остаётся заготовкой. Выход удаляет токен из браузера; серверного отзыва уже выданного токена нет, он действует до истечения срока (по умолчанию 24 часа).

Каталог подключён к PostgreSQL через API, требует входа; добавлены серверная валидация и права владельца/ADMIN. Инструкция актуального запуска — [postgres.md](postgres.md). Загрузка файла, поиск и пагинация пока не реализованы.
