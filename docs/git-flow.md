# Ветки и порядок интеграции

`main` содержит опубликованные релизы, `develop` — интегрированную разработку.
Изменения функциональности готовятся в `feature/*`, проходят проверки и поступают
в `develop` через pull request. Для этих изменений отдельный релиз не создается.

## Текущие изменения

| Ветка | Содержание | Целевая ветка PR |
| --- | --- | --- |
| `feature/auth-postgres` | JWT-регистрация и вход, восстановление сессии, каталог через PostgreSQL, права владельца/ADMIN, инструкции запуска | `develop` |
| `feature/tests` | Тесты клиентских модулей и серверного сервиса, 8 браузерных сценариев, Playwright CI, документация и отчеты | `develop` |
| `feature/test-coverage` | Расширенные тесты обновлённого каталога/JWT, PostgreSQL-интеграция, live Playwright и отчёт ЛР7; основана на `feature/auth-postgres` | `develop` после интеграции `feature/auth-postgres` |

`feature/tests` включает `feature/auth-postgres`: ее браузерные проверки требуют
нового каталога и авторизации. Обе ветки синхронизированы с `develop`.
В функциональную ветку также входит ранее опубликованный в `feature/tests`
прототип клиента и настройка метрик сборки, необходимые для текущего приложения.

Порядок слияния: сначала `feature/auth-postgres` → `develop`, затем
`feature/tests` → `develop`. Используйте merge commit с сохранением истории,
чтобы второй PR распознал уже интегрированную функциональность. Перед слиянием
проверьте результаты GitHub Actions. Feature-ветки в `main` напрямую не сливаются.

## Проверки перед публикацией

```powershell
npm.cmd --prefix client run lint
npm.cmd --prefix client test
npm.cmd --prefix client run build
npm.cmd --prefix client run test:e2e
mvn.cmd -B -f server/pom.xml verify
```

Локально 05.11.2026 прошли ESLint, 23 клиентских модульных теста,
8 браузерных сценариев, 8 серверных тестов, сборки клиента и сервера и Checkstyle.
Playwright использует подготовленные в тестах ответы API; эти результаты
не являются проверкой работающего PostgreSQL. Для такой проверки предусмотрен
`scripts/check_postgres.py` при запущенном API.

На следующем этапе в `feature/test-coverage` проверки расширены до 32 клиентских,
18 браузерных с API-фикстурами, 32 серверных (включая настоящую PostgreSQL) и одного
полного браузерного сценария с API и БД. Добавлен workflow `PostgreSQL integration`.
Актуальный порядок и команды проверок — в [testing.md](testing.md).

Коммиты используют Conventional Commits: `feat`, `test`, `ci`, `docs`, `chore`.
Собранные файлы, результаты тестов, `node_modules`, `.env` и временные файлы
Word исключены из Git. Учебные отчеты DOCX хранятся за пределами репозитория,
в соседнем каталоге `../publication-system-reports/`. Генератор отчета ЛР7
также сохраняет результат в этот каталог. `package-lock.json`, настройки
линтеров, workflow и исходники тестов отслеживаются Git и удаляться не должны.

## Следующая разработка и релизы

Новую независимую feature-ветку создавайте от обновленного `develop`.
Если работа зависит от открытой feature-ветки, явно указывайте эту зависимость
в описании pull request и порядок интеграции.

Когда будет запрошен релиз, создайте `release/<версия>` от `develop`.
После проверки релиз сливается в `main` с тегом `v<версия>` и обратно в `develop`.
Срочные исправления выпущенной версии готовятся в `hotfix/*` от `main`
и также возвращаются в обе основные ветки.
